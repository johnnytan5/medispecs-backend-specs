================================================================================
TIMELAPSE RECORDING SETUP GUIDE
MediSpecs - Automatic Video Recording & Upload to S3
================================================================================

🎬 WHAT IS THIS?
--------------------------------------------------------------------------------
Automatic timelapse recording from your smart glasses camera:
- Captures 1 frame every 2 seconds
- Creates 15-minute MP4 video segments (450 frames)
- Auto-uploads to S3 via your Lambda API
- SQLite tracking for upload retry logic
- Auto-cleanup after 24 hours
- Playback at 30 FPS (smooth timelapse)

Perfect for:
- Daily activity monitoring
- Senior care oversight
- Security/safety review
- Memory recall assistance


🔧 INSTALLATION
--------------------------------------------------------------------------------

Step 1: Install System Packages (Raspberry Pi)
-----------------------------------------------
sudo apt-get update
sudo apt-get install -y ffmpeg

Step 2: Install Python Dependencies
------------------------------------
pip install ffmpeg-python requests

Or install all requirements:
pip install -r requirements.txt

Step 3: Configure Lambda API URL
---------------------------------
Add to your .env file:

LAMBDA_API_URL=https://your-api-gateway-url.amazonaws.com/prod
DEVICE_ID=medispecs_pi_001  # Optional custom ID


📝 CONFIGURATION
--------------------------------------------------------------------------------

Edit config.py to customize settings:

# Enable/disable timelapse
TIMELAPSE_ENABLED = True

# Capture settings
TIMELAPSE_FRAME_INTERVAL = 2  # 1 frame every 2 seconds
TIMELAPSE_SEGMENT_DURATION = 900  # 15 minutes (900 seconds)

# Video settings
TIMELAPSE_VIDEO_FPS = 30  # Playback speed
TIMELAPSE_VIDEO_QUALITY = 80  # Quality (0-100)

# Storage
TIMELAPSE_STORAGE_PATH = "timelapse"  # Local storage directory
TIMELAPSE_MAX_AGE_HOURS = 24  # Delete after 24 hours

# Upload settings
TIMELAPSE_UPLOAD_ENABLED = True
TIMELAPSE_UPLOAD_IMMEDIATE = True
TIMELAPSE_UPLOAD_RETRY_IMMEDIATE = 3  # Immediate retries
TIMELAPSE_UPLOAD_RETRY_INTERVAL = 3600  # Background retry (1 hour)
TIMELAPSE_UPLOAD_MAX_ATTEMPTS = 24  # Max retry attempts


🚀 USAGE
--------------------------------------------------------------------------------

Automatic Start:
----------------
Timelapse starts automatically when you run:
python main.py

You should see:
🎬 Timelapse recording enabled (1 frame/2s, 15min segments)


Manual Control via API:
------------------------
# Start recording
curl -X POST http://localhost:8000/timelapse/start

# Stop recording
curl -X POST http://localhost:8000/timelapse/stop

# Check status
curl http://localhost:8000/timelapse/status


📡 API ENDPOINTS
--------------------------------------------------------------------------------

Control:
--------
POST /timelapse/start         # Start recording
POST /timelapse/stop          # Stop recording
POST /timelapse/complete-segment  # Force complete current segment (manual cutoff)
GET  /timelapse/status        # Service status & progress

Videos:
-------
GET  /timelapse/videos        # List all videos
GET  /timelapse/videos/{id}   # Get video details
GET  /timelapse/videos/{id}/stream  # Download/stream video

Upload Management:
------------------
GET  /timelapse/pending-uploads     # List failed uploads
POST /timelapse/retry-upload/{id}   # Retry specific video
POST /timelapse/retry-all           # Retry all failed uploads

Cleanup:
--------
POST /timelapse/cleanup       # Manual cleanup
DELETE /timelapse/videos/{id} # Delete specific video

Statistics:
-----------
GET  /timelapse/stats         # Storage & upload statistics

📊 STORAGE CALCULATIONS
--------------------------------------------------------------------------------

Per 15-Minute Video:
--------------------
- Frames captured: 450 frames
- Frame size: ~50KB each = ~22.5MB pending
- Video size (MP4): ~20-25MB compressed

Per Day (96 videos):
--------------------
- Total videos: 96 segments
- Storage: ~2.4GB per day

With 24h Retention:
-------------------
- Max local storage: ~2.4GB
- You have 32GB → Plenty of space! ✅


⚙️ HOW IT WORKS
--------------------------------------------------------------------------------

Step 1: Frame Capture (Every 2 seconds)
----------------------------------------
🔄 Background task captures frames
📸 Grabs from face_detection_service.latest_frame
💾 Stores in memory (no disk I/O until video creation)

Step 2: Video Creation (After 450 frames / 15 min)
---------------------------------------------------
🎬 Collects 450 frames
🎥 Creates MP4 using ffmpeg (libx264 codec)
💾 Saves to ./timelapse/videos/{videoId}.mp4
📝 Records in SQLite database

Step 3: Upload to S3 (Immediate)
---------------------------------
1️⃣ POST to Lambda: Create metadata in DynamoDB
2️⃣ GET from Lambda: Get pre-signed S3 upload URL
3️⃣ PUT to S3: Upload video file
4️⃣ UPDATE SQLite: Mark as uploaded

Step 4: Retry Failed Uploads (Every hour)
------------------------------------------
🔄 Background task checks for failed uploads
♻️  Retries up to 24 times (24 hours)
✅ Updates database on success

Step 5: Cleanup (Daily at 3am)
-------------------------------
🧹 Finds videos older than 24 hours
✅ Only deletes if successfully uploaded
🗑️  Removes local files, updates database


🐛 TROUBLESHOOTING
--------------------------------------------------------------------------------

❌ "Timelapse initialization failed"
  → Check ffmpeg installed: ffmpeg -version
  → Install: sudo apt-get install ffmpeg
  → Check permissions on ./timelapse/ directory

❌ "No frames available from camera"
  → Face detection must be running
  → Check camera connected: ls /dev/video*
  → Verify face_detection_service.latest_frame not None

❌ Upload fails: "LAMBDA_API_URL not configured"
  → Add to .env: LAMBDA_API_URL=https://your-url.com
  → Restart server: python main.py
  → Verify URL is correct (test with curl)

❌ Upload fails: "Metadata creation failed"
  → Check Lambda API is accessible
  → Test: curl https://your-lambda-url/videos
  → Check userId parameter matches (default: u_123)

❌ Upload fails: "S3 upload failed"
  → Check S3 bucket permissions
  → Verify pre-signed URL not expired (default: 1 hour)
  → Check file size within S3 limits

❌ "Storage full" or disk space issues
  → Check: df -h
  → Run manual cleanup: curl -X POST http://localhost:8000/timelapse/cleanup
  → Reduce TIMELAPSE_MAX_AGE_HOURS in config.py

❌ Video file corrupted or won't play
  → Check ffmpeg encoding: ffmpeg -i video.mp4
  → Verify all 450 frames were captured
  → Check available disk space during creation

❌ Retry loop not working
  → Check SQLite database: sqlite3 timelapse/timelapse.db
  → Query: SELECT * FROM videos WHERE uploaded=0;
  → Verify upload_attempts < 24


💾 DATABASE QUERIES
--------------------------------------------------------------------------------

Access Database:
----------------
sqlite3 timelapse/timelapse.db

Useful Queries:
---------------
-- List all videos
SELECT video_id, uploaded, upload_attempts, created_at FROM videos;

-- Pending uploads
SELECT video_id, upload_attempts, upload_error FROM videos WHERE uploaded=0;

-- Successfully uploaded
SELECT COUNT(*), SUM(file_size_bytes)/1024/1024 as total_mb 
FROM videos WHERE uploaded=1;

-- Failed uploads needing retry
SELECT video_id, upload_attempts, last_upload_attempt_at, upload_error
FROM videos 
WHERE uploaded=0 AND upload_attempts < 24;

-- Storage usage (not deleted)
SELECT COUNT(*), SUM(file_size_bytes)/1024/1024 as local_mb
FROM videos WHERE deleted_locally=0;
